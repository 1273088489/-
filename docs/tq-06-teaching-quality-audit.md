# TQ-06 教学质量审计与零基础走查

日期：2026-08-11

权威契约见 [teaching-quality-contract.md](./teaching-quality-contract.md)。本文只记录 TQ-06 的检查方法、实际证据、发现和结论，不改写契约。

## 审计结论

- canonical 课程规模为 1 门课程、7 个课时、15 道练习、4 个阶段项目。
- 全部教学对象通过结构化约束和逐项人工内容审校；代表性的第 1 阶段学习路径完成桌面与移动端真实浏览器走查。
- 学习者无需阅读源码即可在页面回答：学什么、为什么、怎么做、交什么、如何判断、如何复盘。
- 页面和公开 API 不暴露练习 `solution`；练习/项目反馈仍是形成性评审，不声称执行代码、测试、Git、仓库或部署检查。
- 练习提示以“定位 -> 概念 -> 路径”显式递进；单个术语命中不会再把整条 rubric 或项目验收标准误报为“有证据支持”。
- 课程、课时、练习和项目 API 已锁定精确公开键集合，并递归拒绝敏感键；首页与演示摘要同步为 7 课、15 练习、4 项目。
- 旧 `demoLesson`、demo 练习和 demo 判分已删除；首页摘要只保留课程展示字段，已登录仪表盘在进度 API 失败时显示真实错误，不制造学习进度。
- 人工走查发现的“注册后导航仍显示登录/注册”问题已用失败 E2E 复现并修复；修复后注册、退出、再登录流程通过。
- 完整 Vitest、Webpack 生产构建和 Playwright 均通过；默认 Turbopack 构建因工作树外 `node_modules` Junction 被 Next.js 拒绝，详见“最终质量门”。

## 零基础浏览器走查

走查环境：Next.js 16.3.0，Webpack 开发服务器，隔离 E2E SQLite 数据库，Mock AI；合成测试账号，不使用真实个人信息。

| 问题 | 学习者在页面得到的答案 | 实际观察 |
|---|---|---|
| 学什么？ | 课程标题/描述、课时“学习目标”、练习题目、项目目标 | 课程、课时、练习、项目四层均可直接读到 |
| 为什么？ | 真实场景、每一步“原因”、核心概念与取舍 | 第 1 课页面无需源码即可解释先确认目录和暂存审查的原因 |
| 怎么做？ | 课时实施步骤、项目步骤、分级提示 | 第 1 课给出 PowerShell/Unix 动作、产出和验证；练习提示按需展开 |
| 交什么？ | 本阶段交付物、练习 prompt、项目交付物 | 仓库/记录/PRD/README 等均为可审查证据，不是笼统“完成项目” |
| 如何判断？ | 完成检查、练习提交前 rubric、项目验收与四级 rubric | 标准在提交前可见；空答案时提交按钮禁用 |
| 如何复盘？ | 课时“复盘与迁移”、项目“复盘问题” | 同时要求解释被放弃方案、失败原因和迁移到新情境 |

视觉证据：

- 桌面课程页 1440px：7 课与 4 项目入口可扫描，无横向溢出。
- 桌面课时页 1440px：九段结构和练习入口可读，无横向溢出。
- 桌面练习页 1440px：题目、4 条标准、边界说明和答题区同时可见。
- 桌面项目页 1280px：项目标题与提交区、指南并列；全部合同段落存在，无横向溢出。
- 移动项目/课时/练习页 390x844：`scrollWidth <= innerWidth`；长中文标题和英文命令换行，无文本遮挡；输入区宽度分别为 343px/293px。

限制：走查只验证平台展示的教学合同与导航，不执行学习者代码，不读取学习者 Git 历史，不访问学习者仓库或部署 URL，也不把未运行的命令/测试写成已通过。
